## The docs quickcheck

Documentation landed on `main` with #55 and now has three workflows. Run this
before trusting the published site, and after any change under `docs/`:

```sh
uv run qm docs audit                        # rebuild + accuracy, 4 dimensions
uv run --with zensical zensical build --clean   # the real build
find site -name '*.html' | wc -l            # 24 at the stamp
```

At `f0ab032`: **0 findings across 4 dimensions**, build clean, 24 pages.

**What each dimension means, because a green audit is not a green build.**
`rebuild` checks the config parses with a standard parser and the inputs exist —
it does **not** run the generator, which is why the build command above is
listed separately. `accuracy` checks links resolve, named repository paths
exist, and no docs page silently shadows a corpus document. None of it reads a
page for correctness.

**Three workflows, and they are not interchangeable:**

| | Trigger | Does |
|---|---|---|
| `docs.yml` | push to `main` **or** `docs` | deploys to Pages. Both triggers kept deliberately |
| `docs-audit.yml` | pull request touching docs | builds and audits. **Rebuild fails the PR; accuracy reports and does not** |
| `docs-draft.yml` | `ready_for_review`, or manual dispatch | builds, banners every page, uploads an artifact. Never deploys |

**The draft is an artifact, not a URL.** Pages serves one site per repository and
`deploy-pages` replaces it wholesale, so publishing a draft there would take the
real documentation down to preview an unmerged branch. A genuine preview URL
needs a second Pages site or an external host, and nobody has decided that.

**`ready_for_review` fires only on the transition.** A pull request that is
already ready will not trigger it; use `gh workflow run docs-draft.yml`.

## What is new since the last handoff

**The ledger** (`records/DRAFT-the-ledger.md`, `ledger.yaml`). Every substantive
action carries what it was predicted to do, written before acting, and what it
cost. `uv run qm ledger --check` refuses a closed entry with no outcome. Its §2
— that the projection precedes the act — is unenforceable by construction and
the record says so.

**Two gates that did not exist.** `commit-signatures` reads the forge rather
than the runner, because verifying a signature needs a key a runner has not got.
`tag-claims` makes the version-tags record mechanical. The declared-and-not-built
count is now zero.

**One deliberate hole, announced.** Commit `35ebca6a` names a model in its
subject and is exempt by full SHA, kept as the worked example the rule is taught
from. `check_attribution.py` prints the exemption and its reason on every run,
and `handbook/gates.md` carries it under what `adr-lint` cannot see. There is a
test asserting exactly one such exemption exists.

**Nine unsigned commits, permanently.** Made with a bypass flag before the rule
had a check. History is not rewritten here, so `ENFORCED_FROM` exempts them by
date and the count is printed as debt on every run. It does not go down.
