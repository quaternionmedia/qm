## What was corrected on the way

**`project/qmcp` was opened as a pull request into `main` (#40), and closed
unmerged.** A `project/<name>` branch is permanent and never merges to `main`;
merging one moves that project's `adr/` into the org namespace, where a
project-local decision reads as binding every project. No committed document
said so — `/cowork` said each project *branch* holds a slot when the tool grants
one per *base*, and `namespace-guard.yml` only fires when the base is
`project/**`, so it could not see it. Both are fixed on #38, along with a
`check_pr_base.py` refusal and an `adr-lint` step that reddens the default
branch if a top-level `adr/` ever reaches it.

**Two defects in the local workflow runner**, both of which produced confident
false results. Step `env:` blocks were never substituted, so `GH_TOKEN` was set
to the literal `${{ github.token }}` and `gh` returned `Bad credentials
(HTTP 401)` — a false red on the slot check. And `GITHUB_HEAD_REF` was never
exported, so a base check saw an empty ref.

**`submodule-check.yml` told a human to run `git ls-remote <url> <sha>`** to
distinguish an unpushed pin from a private remote. `ls-remote` matches ref
names, so it prints nothing and exits 0 for a commit that is perfectly fine —
the advice confirmed the failure it was meant to rule out. Corrected to a
`--depth=1` fetch.

## What neutralising a merge costs later

`project/streaming-infrastructure` is not a defect, and reading it as one was
this session's second interpretive error. The branch exists because `main`
*deleted* the streaming payload — `dec5c9c`, "Move the math workspace and the
streaming project onto their own branches" — and the branch carries it. Its tip
merge says so plainly:

> Neutralises the deletion commit on main without discarding anything here, so a
> future merge from main brings org changes and leaves the payload alone.

That is deliberate, documented, and the right intent. The finding is narrower
and it is about the instrument, not the decision.

**Neutralising a merge declines everything that merge carried, not only the
commit you meant to neutralise.** The tip's tree is byte-identical to its first
parent, so nothing from `81d6967` came across. Git now records `81d6967` as
incorporated, so no later merge revisits it. A file returns only if some *later*
commit on `main` touches it again:

| Path | Commits touching it after `81d6967` | On the branch today |
|---|---|---|
| `REUSE.toml` | 2 | present — a later commit brought it |
| `LICENSE` | 0 | **absent, permanently** |
| `records/DRAFT-outbound-licensing.md` | 0 | **absent, permanently** |
| `records/DRAFT-version-tags-are-claims.md` | 0 | **absent, permanently** |

Merging `main` into it today conflicts in 22 paths, so this is not a routine
propagation and should not be attempted as one.

The generated document is honest about the branch — `behind_corpus: 40`,
`repository: {unknown: 404}`, seed `drift` on both template comparisons. What it
cannot express is that `last_propagation` names `b0265d1`, giving "when did this
branch last take `main`?" a confident, dated answer of 2026-08-08 when the
content answer is "nothing from that merge". A propagation that propagated
nothing still looks like a propagation.

**None of this is urgent and none of it is a rule violation.** It is written
down so the next person merging `main` into that branch knows the three files
will not arrive on their own.

## Two defects fixed in the seed, which reach every project

- **`submodule-check.yml` called a pushed commit unpushed.** It fetched the
  `.gitmodules` URL as written, and a runner has no SSH key, so
  `git@github.com:…` always failed. It now translates to HTTPS, tries both, and
  when both fail says it cannot tell "not pushed" from "private remote,
  unauthenticated runner".
- **`run_workflows_locally.py` ignored `working-directory`.** A step ran at the
  repository root and reported a confident failure about a file one directory
  down. Now resolves step → job → workflow defaults, and a missing directory
  fails loudly rather than silently running at the root.

## The methodological change

§8 of `records/DRAFT-decision-record-discipline.md` is new: a claim about what
facts *mean* must name what else could produce them. It exists because the two
worst errors of this session had entirely true facts underneath — a claimed
independent convergence that was one author and backwards in time, then an
over-correction that deleted the real finding. The retrospective is
`perspectives/2026-08-11-inflation-deflation-and-what-discovery-looks-like.md`.

Unlike every other clause here it has no mechanical check and never will. It is
carried by records naming the alternatives they ruled out.
