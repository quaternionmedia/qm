# Repository layout

!!! info "Source of truth"
    This page describes the structure of [quaternionmedia/qm](https://github.com/quaternionmedia/qm). Cited as: `docs/ref/repo-layout.md`.

## The directory tree

```
qm/
├── PRINCIPLES.md          the charter — what QM believes, and why
├── README.md              this onramp
├── AGENTS.md              governance discovery for coding agents
├── CLAUDE.md              symlink to AGENTS.md (for Claude)
├── TEMPLATE.md            template for new records
├── records/               the org records; the only binding documents
├── registers/             live org-level registers (carried patches)
├── handbook/              policy, status and procedures routed out of record form
├── perspectives/          attributed, dated, non-binding opinion
├── project-seed/          what a new project copies: adr/, ci/, ide/
├── ci/                    org-level tooling, copied nowhere: the status generators
├── docs/                  this documentation site (published to GitHub Pages)
├── governance-status.yaml generated; where every project stands, and when
├── harness-status.json    generated; PR slots, phases claimed, governance evidence
├── .github/               CI workflows, CODEOWNERS, branch-protection config
├── .claude/               the harness commands, symlinked into project-seed/ide/
├── LICENSE                CC-BY-SA-4.0 corpus prose
├── LICENSES/              detailed license texts
├── REUSE.toml             license and copyright metadata
└── [other project files]  git, uv.lock, .vscode, .gitignore, etc.
```

### Key file notes

- **`CLAUDE.md` and `.github/copilot-instructions.md`** are symlinks to `AGENTS.md`, so any tool reading either gets its current bytes.
- **`governance-status.yaml` and `harness-status.json`** are generated by `ci/` scripts and committed; they are not rebuilt in CI on every push. See [handbook/generated-documents.md](https://github.com/quaternionmedia/qm/blob/main/handbook/generated-documents.md) for refresh commands and staleness budgets.

## Project branches

Each adopting project's own `adr/` directory — its decision records, as opposed to the org's — lives on a dedicated branch of *this* repo (`project/<name>`), not copied into the project's own git history. The project vendors this repo as a submodule and checks out its own branch.

See [Branch namespaces](namespaces.md) for the full model and [Forking a new project](../usage/first-project.md) for the walkthrough.

## Generated files

The following files are generated by scripts and must not be edited by hand:

- `governance-status.yaml` — run `python ci/governance_status.py --write governance-status.yaml` to refresh
- `harness-status.json` — run `python ci/harness_status.py --no-local --write harness-status.json` to refresh
- `site/` — generated by `zensical build --clean`; not committed

The `.cache/` directory is generated by zensical during builds; it is self-ignored via `.cache/.gitignore`.
