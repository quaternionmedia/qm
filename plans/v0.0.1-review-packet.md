# Review Packet — v0.0.1

**This is the thing to review. It is not a claim that v0.0.1 is good.**

`records/DRAFT-version-tags-are-claims.md` §2 says a `v*` tag asserts three
things: a human reviewed the change set, a human manually tested it against its
real runtime, and deterministic automated validation passed. An agent can
prepare the third and can lay out the first two. It cannot perform them.

So this page exists to make the review possible, and to be honest that until it
happens **v0.0.1 does not exist** — there is a `main` that is clean and working,
which asserts nothing.

## What a reviewer should actually check

Not the diff. It is 12,000 lines and reading it linearly will not surface what
matters. These five will:

1. **Is the two-gate model right?** Everything else follows from it. If a pull
   request should not be author-merged, most of this change set is wrong.
2. **Read `AGENTS.md` item 3 cold.** It is the most-read passage in the corpus
   and has been measured as 840 words, zero paragraph breaks, zero questions.
   Ask whether it would survive contact with a stranger.
3. **`EXEMPT_SUBJECTS` in `check_attribution.py`.** One commit is exempt by
   full SHA. Decide whether the reason holds, because the list is easier to
   grow than to shrink.
4. **`ENFORCED_FROM` in `check_signatures.py`.** Nine unsigned commits are
   permanently exempt by date. Decide whether that is a debt worth carrying.
5. **The ledger's four missed projections.** They are the honest part of the
   record and the fastest read of what went wrong.

## What must be manually tested, and by a human

§2's second clause. The corpus's "real runtime" is a person following it with
no session context. Nothing automated reaches this.

```sh
uv run qm --help          # is the surface legible without explanation?
uv run qm docs states     # does a stranger learn what binds them?
uv run qm gates           # is "advisory" understood?
uv run qm ledger          # do the misses read as honest or as decoration?
```

Then the thing no command covers: **open `handbook/handoffs/session-2026-08-15.md`
and try to act on it without asking anyone anything.** Where you have to ask, the
corpus has failed, and that is the finding.

## The automated gate, and what it did not cover

```
uv run qm test                            561 passed, 0 skipped
uv run --extra preflight qm preflight     29/29 executed steps
uv run qm docs audit                      0 findings across 4 dimensions
uv run qm restatements / review / ledger --check / docs check    all clean
```

Determinism, per §3: the suite reports **no skips, reruns, retries, xfails or
errors**, verified by `check_tag_claims --test-output`. That satisfies §3 as far
as the check can see, which is not the same as the suite being deterministic —
a suite that is nondeterministic and silent about it passes.

**Not covered, and this list belongs in the tag annotation:**

- Nothing is enforced at the merge boundary. `gh api .../rulesets` returns `[]`.
  Every gate is advisory; each reports, and a human can merge past all of them.
- No `v*` tag-protection ruleset exists, so §7 of the tag record is still
  customary for tag *creation*.
- The 16 records have never been read as one body. The semantic review is
  unstarted and it is the one milestone requirement nothing can measure.
- Nothing has ever been ratified. The five-step path has never been walked.
- Three of `adr-lint`'s four sub-checks cannot fire on any ref CI runs against.
- The docs audit does not run the site generator, and no check reads a page for
  correctness.
- One document's state cannot be established.

## The annotation, for the human cutting the tag

`check_tag_claims.py` requires all four fields. The first two are **yours to
write and yours to mean** — they are left blank on purpose, and a tag whose
annotation cannot state the manual test is a tag that should not exist yet.

```
git tag -a v0.0.1 -m "Governance mechanised: two-gate model, the qm CLI, four gates.

Reviewed-by:
Manually-tested:
Automated-gate: 561 tests, 0 skipped; 29/29 preflight steps; docs audit clean at 0e958c0
Not-covered: nothing enforced at the merge boundary (0 rulesets); no v* tag-protection ruleset; the 16 records have never been read as one body; nothing ratified; 3 of adr-lint's 4 sub-checks cannot fire in CI; 9 unsigned commits exempt by date; 1 commit subject exempt by SHA
"
```

**Do not cut this tag on an agent's say-so.** §1 of the tag record makes it a
human act, and this page is the preparation, not the permission.

## What would make the review fail, honestly

If any of these is true, v0.0.1 should not be tagged:

- The two-gate model is wrong, or was adopted too fast on one correction.
- `AGENTS.md` item 3 still cannot be read cold by someone outside QM.
- The exemptions are load-bearing rather than incidental.
- The handoff cannot be acted on without asking the author.
- The ledger's misses read as performance rather than record.
