# Blockers — v0.0.1

**A blocker here is a decision only a human can make, which the tag waits on.**
Not a bug and not a task: each one has options, each option has a cost, and
none of them is a default a tool may pick.

`plans/v0.0.1-review-packet.md` is what a reviewer reads. This is what a
reviewer must *decide* before the tag exists.

---

## 1. The `private-names` gate has no way to see private repositories in CI

**Status: decided, 2026-08-16.** Not a blocker. Recorded here because the
reasoning is the part worth keeping.

**The obligation moved to the party who makes a repository private.**
`records/DRAFT-going-private-is-an-act-with-obligations.md`: whoever flips the
switch owns removing that repository's name from this corpus, and the corpus
does not watch for the transition.

Every way of watching costs something permanent for an event somebody already
knows about at the moment it happens:

| | measured cost |
|---|---|
| Organisation-read credential | this repository's first secret, a rotation duty, and silent return to `unverified` on expiry |
| Committed digest list | 24 of 33 names are all-letter words, median length 7, minimum 3 — the list is recoverable, so the mechanism publishes the secret |
| Continuous polling | a host-reading check that reds an unrelated pull request for a reason its author cannot fix |

**What is deployed:** the workflow is removed. `uv run qm private-names` stays
as a preflight on a machine holding the gitignored companions, and
`ci/gate-registry.yaml` records `gates: []` with a `cannot_see` row saying it
cannot see a repository becoming private after the fact.

**What was given up, plainly:** a repository that goes private today, whose name
is already in the tree, produces no signal. Nothing goes red. The next thing
that notices is a person reading.

## 2. Two private repository names are in public history

**Status:** open, and permanently so unless a decision changes it.

Both names are in this repository's public git history from `2b50bd6`. The
working tree is redacted; history is not, and a rewrite is forbidden here.

Registered as `private-names-in-published-history` in
`ci/exception-registry.yaml`. Its removal condition names the only two things
that would retire it: **make the repositories public**, or **decide a history
rewrite is warranted**. Both are the operator's call.

Relevant to the tag because a reviewer should know the exemption exists rather
than discover it.
