# Blockers — v0.0.1

**A blocker here is a decision only a human can make, which the tag waits on.**
Not a bug and not a task: each one has options, each option has a cost, and
none of them is a default a tool may pick.

`plans/v0.0.1-review-packet.md` is what a reviewer reads. This is what a
reviewer must *decide* before the tag exists.

---

## 1. The `private-names` gate has no way to see private repositories in CI

**Status:** open. The gate is built, tested and passing locally; it is
**deployed non-blocking** because it cannot get its input on a runner.

### What is true

`ci/check_private_names.py` refuses a private repository's name used as a
repository in any tracked file. It needs a list of which repositories are
private. Two sources exist and neither works in CI:

| source | works locally | works in CI | why |
|---|---|---|---|
| `--source local` | yes | no | reads `inventory-private.json` and `ci/workspace-private.yaml`, both gitignored |
| `--source host` | yes | **no** | `github.token` is scoped to this repository; `orgs/<org>/repos?type=all` returns no private repositories, so the check reports `unverified` |

The failure is quiet in the worst way: the API call *succeeds* and returns a
list with nothing private in it. Only the `unverified` state — which exists
because an empty result must never read as clean — keeps that from passing as a
green check.

The tree is clean today, verified locally against all 33 names. What is missing
is the gate, not the remediation.

### Options

**A. An org-read token as a repository secret.** A fine-grained PAT with
organization metadata read, stored as `ORG_READ_TOKEN`. The gate then works as
designed: it sees the live list, and it fires when a repository becomes private
while its name is already in the tree — the case no offline check can catch.

*Cost:* one credential to create, store and rotate. A secret that expires makes
the gate silently return to `unverified`, so its expiry becomes something to
watch. Fork pull requests do not receive secrets, so the gate is inert on those.

**B. Commit digests of the names.** A committed file of SHA-256 hashes, one per
private repository name. CI hashes each identifier-shaped token in the tree and
compares. No token, no network, works on a fork.

*Cost:* a digest list is testable offline. Anyone can hash a guess and check it,
and several of these names are three, five and nine letters — for those this is
close to no protection. It also has to be regenerated whenever the org gains or
renames a private repository, and a stale list silently under-checks.

**C. Local only, and say so.** Drop the workflow. The check stays a preflight
step on a machine that has the companions, and `ci/gate-registry.yaml` records
that `main` is not gated on this.

*Cost:* the next private name reaches `main` unless a human remembers to run it.
This is the state the corpus calls a declared gap: honest, and weaker.

### What is deployed while this is open

Option C's *behaviour* with A's *machinery*: the workflow runs, reports
`unverified`, and exits 0 rather than failing every pull request for a reason
its author cannot fix. `ci/gate-registry.yaml` records `gates: []` — this does
not gate `main` — and its `cannot_see` row says why. Switching to option A is a
two-line change to the workflow once the secret exists.

### Who decides

The operator. It is a credential-and-threat-model question about their own
organisation, and the three options differ in what they leak, not in what they
cost to build.

## 2. Two private repository names are in public history

**Status:** open, and permanently so unless a decision changes it.

Both names are in this repository's public git history from `2b50bd6`. The
working tree is redacted; history is not, and a rewrite is forbidden here.

Registered as `private-names-in-published-history` in
`ci/exception-registry.yaml`. Its removal condition names the only two things
that would retire it: **make the repositories public**, or **decide a history
rewrite is warranted**. Both are the operator's call.

Relevant to the tag because a reviewer should know the exemption exists rather
than discover it.
