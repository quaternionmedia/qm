## What it demonstrates

`qmcp` decides what a topology is and emits it as a document. `dossier` draws
that document in a terminal. `codecartographer` draws the same document as a
graph. The three then **agree about what they drew** — same boxes, same arrows,
same edges nobody measured — and the agreement is checked rather than looked at.

Each window runs under **its own project's interpreter**, in its own process,
with JSON on a pipe between them. That is not a convenience: the repositories do
not depend on each other, and a demo that imported all three would pass in a way
no user's machine reproduces.

## The run, on the stated fixture

```
[1] qmcp emits the topology
    topology     codecartographer at level 2
    data         fixture
    boxes        4
    arrows       3, of which 1 unmeasured
    encoding     4 channel(s) declared

[2] dossier draws it
    1 edge(s) drawn as unmeasured
    | codecartographer  |  level 2
    |   what one project is related to
    |
    |   (codecartographer) ==> [dossier]   part-of
    |   (codecartographer) ==> [qmcp]   crosses
    |   (codecartographer) -?> [rad]   crosses
    |
    |   dossier: 91% -- mentions
    |   qmcp: 34% -- mentions

[3] codecartographer draws it
    1 edge(s) drawn as unmeasured
    | 2 of 3 edge(s) measured; the rest are drawn dashed because nobody looked
    | subject -> r0  solid    w=4.17  part-of
    | subject -> r1  solid    w=2.06  crosses
    | subject -> r2  dashed   w=1.60  crosses

AGREEMENT
  dossier              4 boxes, 3 arrows, 1 unmeasured
  codecartographer     4 boxes, 3 arrows, 1 unmeasured

  2 windows agree about every box, every arrow, and which edges nobody measured.
```

**The unmeasured edge is the point.** `rad` is drawn `-?>` in the terminal and
dashed in the graph — never as a thin line. Nobody measured that relation, and a
thin line would say somebody measured it and found it weak. Those are opposite
claims about the same edge, and keeping them apart is the one thing both windows
are tested for.

## What the demo found

Three defects, none of which the fixture could have shown.

**One address was drawn as several boxes.** `from_relations` keyed a box on the
loop index, so three threads' readings of one delta became three nodes carrying
the same label and the same note — which reads as three deltas that happen to
share a name. An address is what says two readings are about the same thing.
Fixed in `qmcp`; the arrows are deliberately *not* merged, because three
observations with three weights are not one observation.

**Parallel edges vanished into a `DiGraph`.** `networkx.DiGraph` keeps one edge
per ordered pair and silently replaces the rest. Once the boxes were correctly
merged, the graph drew one line where three were measured, with no error and no
warning. Fixed by `MultiDiGraph` in `codecartographer`.

**The agreement check compared sets.** With parallel arrows it would have
compared `{subject->r0}` against `{subject->r0}` and passed while one window
dropped two edges. Now compares sorted lists.

## The seam was tested and the seam was not deployed

**The demo passed for a day while nothing at either port could draw anything.**
Running each window's code as a subprocess proves the two renderers agree about a
document. It says nothing about whether either is *reachable*, and neither was:

- **`qmcp` served no topology route at all.** `/v1/topology` did not exist, so
  no front end could fetch a view. The demo worked only because it ran the
  harness's code in a subprocess, which is not what a front end does.
- **`codecartographer` had a renderer nothing routed to.** `topology_service.py`
  resolved payloads into channels correctly and was imported by exactly one
  thing: its own test. "codecarto is the harness's front end on the web" was
  true of a module and false of the product.

Both are closed. The harness serves `/v1/topology`, `/v1/topology/encoding` and
`/v1/topology/shape/{kind}` anywhere it is bound, and
`/v1/topology/relations/{subject}` **only on loopback** — the readings are
derived from a person's conversations and follow the archive's own rule, absent
rather than refused off loopback, because a 403 tells a caller the archive is
here. The web front end serves `/topology` and `/topology/data`.

`uv run qm demo --over-http` compares the deployed processes: the topology comes
off the harness's socket and the web front end is *asked what it drew*. Every
answer comes from a process somebody could have opened in a browser.

## Reached through `qm`, like everything else

The demo was first written as `protocols/trio_demo.py` and documented by that
path — a second entry point beside `uv run qm`, which `ci/cli.py`'s own header
says must not exist. It is `uv run qm demo` now, with options.

That correction generalised: **four modules in `ci/` had a `main` and no
route**, among them a gate written the same day. Each worked perfectly for
somebody who knew its path and did not exist for anybody reading
`uv run qm --help`. All four are routed —
`demo`, `mathematics`, `patterns`, `session` — and
`ci/tests/test_cli.py` now fails on a runnable module nothing reaches, so the
next one is caught by the suite rather than by a reader.

The exemption is earned rather than listed: a module invoked by another module
or a workflow is a library with a debug entry point, not an operation, and the
test asks whether anything else in the repository names it.

## What was checked by breaking it

Three attempts to satisfy the agreement check while doing what it forbids, each
confirmed to exit non-zero:

| Attempt | Caught as |
|---|---|
| One window silently drops an arrow | `drew 3 arrow(s) and ... drew 2` |
| One window calls an unmeasured edge measured | `disagree about what is known` |
| Parallel arrows collapsed to a set | `same pairs, different counts` |
| `--window` narrowed to one window, reporting success | `agreeing with itself` |
| The `demo` route removed, leaving the module runnable | the reachability test |

The third would have passed before the set-to-list repair, which is why it is
listed: the hole was real and was found by trying to walk through it.

The fourth is the option that could have weakened the whole check. `--window`
narrows what draws, and the obvious implementation lets a single window run and
report success — one window agreeing with itself. It exits 1 instead, and says
why.

## What this did not establish

- **That the topology is right.** Both windows would faithfully draw a wrong
  one. This checks the seam, not the truth on either side of it.
- **That the two pictures look alike.** They must not — one is a terminal and
  one is a graph. Agreement is about content, never appearance.
- **Anything about a machine without the siblings.** The demo needs `qmcp` and
  `dossier` beside the clone; without them it exits 1 and says so rather than
  printing a summary of two windows out of three.
- **Anything on a hosted runner.** Most of `ci/tests/test_trio_demo.py` skips
  where the siblings are absent, with a reason.
